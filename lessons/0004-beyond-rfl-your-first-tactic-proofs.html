Beyond rfl — Your First Tactic Proofs

rfl works when both sides are the same by definition. Tactic proofs handle everything else.

🔗 Mission Connection

Your mission: prove theorems in set theory and logic. The first theorem you'll learn to prove today — P ∧ Q → Q ∧ P — is a propositional tautology. The tactics you'll learn (intro, cases, simp, apply) are the same ones you'll use for every set identity, De Morgan's law, and relation property that follows.

This lesson is the bridge from "rfl works" to "I can prove things that require reasoning."

1. The Limit of rfl

In Lesson 3, you proved two theorems with rfl:

theorem double_eq_add_self (n : Nat) : double n = n + n := rfl

theorem hello_greets (name : String) : hello name = s!"Hello, {name}!" := rfl

These work because double n is defined as n + n, and hello name is defined as s!"Hello, {name}!". The compiler sees they are syntactically the same after unfolding definitions.

But look at this — you already saw it fail in Lesson 3:

theorem maxSpec_self (a : Nat) : maxSpec a a = a := rfl
-- FAILS! Not definitionally equal.

maxSpec a a expands to if a > a then a else a. Whether that equals a depends on whether a > a is false — a fact that requires reasoning, not just definition unfolding.

rfl is for definitional equality. Tactic proofs are for propositional equality. Most interesting theorems are the second kind.

2. The by Block — Entering Tactic Mode

Instead of giving a proof term directly (rfl), you can write by followed by a block of tactics — commands that tell Lean how to transform the goal step by step:

theorem add_zero (n : Nat) : n + 0 = n := by
  simp

Read this as: "To prove n + 0 = n, use the simp tactic (which knows about arithmetic identities)."

When you write by, Lean enters tactic mode. The goal is the proposition after the colon. Each tactic modifies the goal until it's proved.

💡 Key Insight: Tactic Mode

A by block contains a script of tactics. Lean runs the script and checks that the final result is a valid proof. Think of it like a recipe: "first do this, then do that, and at the end the goal should be closed."

Tactics are what make Lean a proof assistant — you guide the proof step by step, and Lean checks each step.

3. Your First Tactic: simp

The simp tactic tries to simplify the goal using a database of known rewrite rules. It's the Swiss Army knife of Lean tactics.

theorem add_zero (n : Nat) : n + 0 = n := by
  simp

simp knows that n + 0 simplifies to n for natural numbers. It closes the goal automatically.

Let's prove a second one:

theorem zero_add (n : Nat) : 0 + n = n := by
  simp

4. Introducing intro — Handling Implication

Your mission includes proving logic tautologies like P ∧ Q → Q ∧ P. The → means "implies." To prove an implication, you assume the left side and try to prove the right side.

The intro tactic does exactly that: it takes the premise of an implication and adds it to your context as a hypothesis.

theorem imp_refl (P : Prop) : P → P := by
  intro h
  exact h

Walk through what happens:

  1. The goal is P → P
  2. intro h changes the goal to P and adds h : P as a hypothesis (the assumption "P is true")
  3. exact h says "the goal is exactly the hypothesis h" — done!

💡 How intro Works

Think of proving P → Q as a function: you receive a proof of P and must produce a proof of Q. That's exactly what intro h does — it says "assume h : P, now prove Q."

This is the Curry-Howard correspondence in action: implication is function type, and intro is lambda abstraction.

5. Breaking Things Apart with cases

The cases tactic breaks down a hypothesis that is a compound proposition. For P ∧ Q, it splits it into two separate hypotheses. For P ∨ Q, it creates two subgoals (one for each case).

theorem and_comm_imp (P Q : Prop) : P ∧ Q → Q ∧ P := by
  intro h
  rcases h with ⟨hp, hq⟩
  exact And.intro hq hp

Walk through:

  1. intro h — assume h : P ∧ Q
  2. rcases h with ⟨hp, hq⟩ — break h into hp : P and hq : Q
  3. exact And.intro hq hp — construct Q ∧ P using the swapped hypotheses

rcases is a more powerful version of cases — it pattern-matches the hypothesis and gives names to its components. The ⟨⟩ syntax constructs or destructs structures (like And).

Note: And.intro hq hp is the proof term for constructing an And. It takes two arguments: the proof of the left side and the proof of the right side.

Try it with constructor instead

An alternative way to prove the same theorem:

theorem and_comm_imp' (P Q : Prop) : P ∧ Q → Q ∧ P := by
  intro h
  have hp : P := h.left
  have hq : Q := h.right
  constructor
  · exact hq
  · exact hp

constructor breaks a goal of the form A ∧ B into two subgoals: prove A, then prove B. The bullets (·) separate the subgoal proofs.

6. Handling Or with cases

Proving P → P ∨ Q is similar, but uses Or.inl (left case) and Or.inr (right case):

theorem or_intro_left (P Q : Prop) : P → P ∨ Q := by
  intro hp
  exact Or.inl hp

Or.inl hp says "prove P ∨ Q by providing a proof of the left side (P)." Or.inr would prove it from the right side.

7. Your First Tactic: apply

The apply tactic matches the current goal against the conclusion of a known theorem or hypothesis, and if it matches, sets up the theorem's premises as new subgoals.

For example, suppose you have h : P → Q and your goal is Q. Then apply h changes the goal to P — because if you can prove P, then h gives you Q.

theorem apply_example (P Q : Prop) (h : P → Q) (hp : P) : Q := by
  apply h
  exact hp

Walk through:

  1. Goal is Q, we have h : P → Q and hp : P
  2. apply h — changes goal to P (the premise of h)
  3. exact hp — closes the new goal

theorem not_and_or_not (P Q : Prop) : ¬(P ∧ Q) → ¬P ∨ ¬Q := by

  -- h : ¬(P ∧ Q), we need ¬P ∨ ¬Q
  -- This requires classical logic (by_cases or em)
  sorry

Hint: This theorem requires classical logic (the law of excluded middle). You can use by_cases hp : P to split into two cases: one where P is true, one where it's false.

Solution (try yourself first!) 
theorem not_and_or_not (P Q : Prop) : ¬(P ∧ Q) → ¬P ∨ ¬Q := by
  intro h
  by_cases hp : P
  · -- if P is true, then Q must be false (otherwise P ∧ Q would hold)
    by_cases hq : Q
    · exfalso; exact h (And.intro hp hq)
    · right; exact hq
  · -- if P is false, we're done
    left; exact hp

New tactics used: by_cases (case split on a proposition), exfalso (change goal to False), left/right (pick side of an Or). Don't worry if this one is hard — it's a stretch exercise.

What You Learned

  • rfl only works for definitional equality — most theorems need tactic proofs
  • A by block enters tactic mode, where you guide the proof step by step
  • simp simplifies goals using known identities
  • intro handles → (implication) by assuming the premise
  • rcases breaks compound hypotheses (∧, ∨) into parts
  • apply matches a goal to the conclusion of a theorem
  • exact closes a goal when you have a proof that matches exactly
  • You proved your first logic theorems: and_comm_imp, or_intro_left, modus ponens

New Glossary Terms

  • by block — enters tactic mode for writing step-by-step proofs
  • intro — assume the premise of an implication
  • apply — match a goal to a known theorem's conclusion
  • rcases — destruct a compound hypothesis with pattern matching
  • simp — simplify the goal using rewrite rules
  • constructor — break a ∧ goal into its two components
  • exact — close a goal when a hypothesis matches it exactly
